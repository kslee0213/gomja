# DART 재무제표 추출 및 엑셀 생성

기업명 하나를 입력받아 DART Open API로 재무제표를 수집하고, 최근 12개 분기와 최근 5개 사업연도 재무제표에 투자분석·가치평가·결론까지 담은 엑셀 파일을 만든다. 아래 순서를 그대로 따른다. 버전별 변경 이력과 각 규칙이 생긴 배경은 `CHANGELOG.md` 참고(작업 시에는 이 파일만 따르면 된다).

> **절대 규칙: "OO 년 분석해줘" / "OO 연 분석해줘"는 확인 질문 없이 즉시 전체 파이프라인을 실행한다.** 이 표현은 그 자체로 "가치평가_결론+재무제표+투자분석+투자판단 종합+버핏멍거_가치평가를 전부 담은 파일 하나(7개 시트)"를 뜻하는 완결된 지시다. "재무제표만 원하는지, 가치평가까지 원하는지"를 되묻지 않는다. 진행 방식이 실제로 여러 갈래일 때(분기 명시, 나열/비교 의도 불명확 등)만 범위 확인 질문을 쓴다. 사용자가 명시적으로 "재무제표만", "투자분석 빼고"라고 말한 경우에만 5-3단계를 건너뛴다.

## 0. 설정

| 항목 | 기본값 | 설명 |
|---|---|---|
| `DART_API_KEY` | (사용자 제공, **필수**) | 대화에 없으면 시작 전에 요청. 매 스크립트 실행 시 `--api-key` 인자로 전달. 값을 요약·로그·산출물에 노출하지 않는다. |
| `KRX_AUTH_KEY` | (사용자 제공, **필수**) | 주가 연동 지표(PER·PBR·PSR·시총)와 가치평가 전체에 필요. `fetch_stock_price.py --auth-key`로 전달. `data-dbg.krx.co.kr` 호출이므로 허용 도메인 필요. 키 발급과 별개로 KRX 마이페이지에서 "유가증권 일별매매정보" 서비스 이용 승인이 있어야 하며, 없으면 "Unauthorized API Call" 에러가 난다. |
| `FS_DIV` | `CFS`(연결) | 응답이 비면 `OFS`(별도)로 자동 재시도. 사용한 구분은 연간_재무제표 상단에 연도별로 표기된다. |
| 분기/연도 수 | 12 / 5 | |
| 파일명 | `{기업명}[_연간|_분기]_{YYYYMMDD}.xlsx` | 접미사는 0-1a 참고. |
| 시장 구분 | KOSPI(corp_cls='Y')만 | company.json으로 확인, 코스닥/코넥스면 사용자 확인 후 진행. |

**작업 시작 전 필수 확인**: 대화에 두 키가 다 있는지 먼저 본다. 없으면 스크립트 실행 전에 요청한다(둘을 한 번에 물어도 됨). KRX_AUTH_KEY만 없으면 "주가 연동 지표가 전부 비는데 이대로 진행할지" 확인하고, 사용자가 "일단 진행"이라고 하면 키 없이 진행 후 요약에서 빈 항목을 안내한다.

## 0-1a. 연간/분기 — 어느 기간으로 만들지

`build_workbook.py`/`build_comparison_workbook.py` 둘 다 `--period {annual|quarterly|both}`를 받는다.

- 요청에 "년"·"연간"·"연도"·"사업연도" → `annual` (접미사 `_연간`)
- 요청에 "분기" → `quarterly` (접미사 `_분기`. 분기 파일에는 투자분석·가치평가가 없다 — 연간 데이터 전용)
- 둘 다 없으면 → `both` (접미사 없음)
- 둘 다 명시되면 `annual`과 `quarterly`를 각각 실행해 파일 2개를 만든다(`both`로 합치지 않는다).

예: "HD한국조선해양 년 분석해줘" → `--period annual` 실행 후 5-3단계까지 자동 진행 → 가치평가_결론(맨 앞)·연간_재무제표·지표_연간·투자분석·원본데이터·투자판단 종합·버핏멍거_가치평가 **7개 시트**가 담긴 파일 하나. 이 전체가 기본 동작이며 범위를 되묻지 않는다.

## 0-1. 여러 기업 — "나열" vs "비교"

- **단순 나열**(비교 표현 없음): 기업마다 1~6단계를 독립 반복해 파일을 따로 만든다.
- **"비교"·"나란히"·"vs" 포함**: 1~4단계는 기업별로 수행해 캐시를 쌓고, 5단계에서 `build_comparison_workbook.py "<corp_code1>:<기업명1>" "<corp_code2>:<기업명2>" ... --period <...>`를 한 번만 실행한다. 산출물은 `{기업명 나열} 비교[_연간|_분기]_{YYYYMMDD}.xlsx`, 보이는 시트는 `12분기 비교`/`최근5년 비교`(표 + 지표당 꺾은선 차트 1개, 회사=계열, 지표 19개 전부 꺾은선)이고 회사별 상세 시트는 감사용 숨김. 회사 간 보유 기간이 다르면 합집합 축을 쓰고 없는 구간은 0이 아니라 공백(끊김)으로 둔다.

## 1. 기업 고유번호(corp_code) 조회

`scripts/corp_code_lookup.py --api-key <키> "<기업명>"` — corpCode.xml(7일 캐시)에서 매칭. 동일명이 여러 개면 후보를 보여주고 사용자 선택을 받는다. company.json으로 `corp_cls`를 확인해 KOSPI(Y)가 아니면 사용자에게 확인한다.

## 2. 대상 연도·보고서 산정

- 연간: 최근 5개 사업연도의 사업보고서(`11011`).
- 분기: 최근 12개 분기를 채우는 데 필요한 보고서 — `11013` 1분기, `11012` 반기, `11014` 3분기, `11011` 사업보고서. 아직 공시 전인 최신 분기는 건너뛰고 그 이전부터 역순으로 12개를 채운다(`status=013`이면 미공시).

## 3. 재무제표 원자료 조회

`scripts/fetch_financials.py --api-key <키> <corp_code> <연도> <보고서코드>`로 (연도, 보고서) 조합마다 `fnlttSinglAcntAll.json`을 호출해 `cache/{corp_code}_{연도}_{reprt}_{fs_div}.json`에 저장한다. 계정 매칭은 `account_nm`이 아니라 `account_id` 기준(코드가 처리). 상세 코드표는 `references/dart_api_reference.md`.

**⚠ 진행 중인 최신 연도도 반드시 조회한다.** 최근 5개년 사업보고서 조회 후, 다음 연도의 사업보고서가 아직 없으면 ① 그 연도의 최신 분기/반기 보고서(11013→11012→11014 순으로 가장 늦은 것)와 ② **전년도의 같은 보고서**를 추가 조회한다. `build_workbook.py`는 캐시에 있는 파일만 읽으므로 이 두 호출을 빠뜨리면 에러 없이 "{연도}(E)" 컬럼이 조용히 안 생긴다(헤더로 확인 가능).

## 4. 분기 실적 계산 규칙

- **재무상태표(BS)는 시점(저량)**: 각 분기말 보고서의 `thstrm_amount`를 그대로 쓴다. 뺄셈 금지.
- **손익·현금흐름(IS/CIS/CF)은 흐름(유량)**: 두 금액 필드를 구분한다 — `thstrm_amount`(당기)와 `thstrm_add_amount`(연초부터 누적).
- **⚠ 반기보고서(11012)의 `thstrm_amount`는 회사에 따라 "6개월 누적"일 수도, "2분기 3개월 단독"일 수도 있다**(후자면 누적이 `thstrm_add_amount`에 있음 — HD한국조선해양 실데이터로 확인). 그래서 누적값이 필요한 곳에서는 항상 **add 필드가 있으면 add, 없으면 thstrm**을 누적으로 쓴다(코드에 반영됨).
- 분기별 계산: **1분기** = 1분기보고서 값 그대로 / **2분기** = 반기 누적(위 규칙) − 1분기 / **3분기** = 3분기보고서 값 그대로 / **4분기** = 사업보고서(연간) − 3분기보고서의 **9개월 누적(`thstrm_add_amount`)**. 3분기 `thstrm_amount`(3개월 단독)를 빼면 "1·2·4분기 합"이 나오는 흔한 실수를 하지 않는다.
- 누적 필드가 없는 계정(현금흐름 항목 등)의 4분기는 "연간 − 1~3분기" 폴백으로 계산하되, **같은 해 1~3분기 열이 시트에 실제로 있을 때만** 쓴다(12분기 창의 첫 연도처럼 잘린 경우 빈 칸으로 둔다).

## 4-1. 투자분석용 추가 데이터 (5단계 전에, 실패해도 5단계는 진행)

1. **DART 추가 공시 4종**: `scripts/fetch_extra_disclosures.py --api-key <키> <corp_code> <최근 사업보고서가 있는 연도> 11011` — 주식총수·배당·최대주주·자기주식.
2. **KRX 종가**(키 있을 때만): 연도별 결산일 기준 `scripts/fetch_stock_price.py --auth-key <키> <종목코드> <YYYY1231>`. 휴장일이면 스크립트가 자동으로 거슬러 올라간다. **추정(E) 연도는 결산일이 아니라 "오늘 기준 가장 최근 영업일"로 조회한다**(주말이면 직전 금요일 — `build_workbook.py`가 같은 규칙으로 날짜를 기대하므로 어긋나면 (E) 행이 빈다. 헷갈리면 오늘 날짜로 조회하고 반환된 `used_date`를 믿으면 된다).

## 5. 엑셀 작성

```
python scripts/build_workbook.py <corp_code> <기업명> --period <annual|quarterly|both> [--outdir /mnt/user-data/outputs]
```

`/mnt/skills/public/xlsx/SKILL.md` 규칙(글꼴·수식·recalc 검증)을 함께 따른다. 생성되는 시트:

| 시트 | 내용 |
|---|---|
| 분기_재무제표 / 연간_재무제표 | 행=계정과목(BS→IS→CIS→CF), 열=기간. 모든 셀은 숨김 "원본데이터" 시트를 참조하는 수식(감사 가능, 하드코딩 금지). 연간에는 사업보고서가 없는 진행 연도가 있으면 "{연도}(E)" 추정 컬럼이 자동 추가된다 — 계산 규칙: 전년 실적 × (당해 누적 ÷ 전년 동기 누적), BS는 최신 분기말 잔액 그대로, 전년 동기가 0 이하이거나 부호가 다르면(흑자/적자 전환) 지어내지 않고 빈 칸. |
| 지표_분기 / 지표_연간 | 기본 지표 14개 + 비율 6개(자기자본비율·부채비율·매출총이익률·원가율·영업이익률·순이익률), 표 오른쪽에 차트 임베드(꺾은선 5 + 비율 막대 1). |
| 투자분석 (연간 전용) | A 회사 개황 / B 재무지표(건전성·수익성·성장성·활동성) / C 위험신호 6종 / D 청산가치(적용비율 셀 참조식) / E CCC / F FCF / G 현금흐름 3단 / H DuPont / I ROIC·NOPLAT(간이) / J 구성비 / K 외환손익 / L 주가 연동(종가·시총·PER·PBR·PSR) / M 배당·대주주·자기주식 / N 투자판단 자동평가(A~E 등급 + 근거 메모) + 섹션별 차트 12개. |
| 원본데이터 (숨김) | DART 원본값(억원 환산), 모든 시트의 유일한 소스. |

- N섹션 등급 규칙: 최근 5개년 중 기준 충족 연수로 A(5)~E(0~1), 기준 미달이어도 5년 연속 개선이면 A로 승격(사용자 지정 규칙). 기준값: 재무건전성(자기자본비율 40%↑·부채비율 200%↓·유동비율 100%↑), 수익성(영업이익률 5%↑·ROE 10%↑·ROA 5%↑), 성장성(매출 10%↑·영업이익 +·총자산회전율 1.0↑), PBR 1.0 미만·PER 15배 미만(주가 캐시 필요, **순이익·자본이 0 이하인 연도는 판정 제외**), 배당성향(30%↑A/20%↑B/0초과 C). 사업역량은 자동 평가하지 않고 "(직접 입력)"으로 남긴다.
- 계정명 매칭에 실패한 지표는 값을 지어내지 않고 빈 칸 + 시트 하단 빨간 경고로 남기고, 완료 요약에서 사용자에게 알린다(`missing_indicators` 필드).

### 구현 불변 규칙 (스크립트 수정 시 반드시 유지 — 전부 실제 버그·실데이터에서 나온 규칙)

1. **콤보(보조축) 차트는 반드시 "1차=막대 + 보조축=꺾은선"** 조합만 쓴다. 막대+막대는 실제 Excel에서 축이 뒤바뀌고 겹친다(스크린샷으로 확인된 버그).
2. **억원 환산은 `write_raw_sheet()` 한 곳에서만** 한다(원본데이터가 유일한 소스라 전 시트에 자동 전파). 예외 2개: "종가"는 주당 가격이라 환산 금지, "시가총액"은 별도 계산 경로라 직접 나눠야 한다 — 안 그러면 PER/PBR가 1억 배 틀어진다.
3. **계정은 `account_nm` 기준으로 병합**하고 그 이름의 모든 account_id를 별칭으로 들고 순서대로 시도한다. DART는 같은 회사 같은 계정에도 분기마다 다른 account_id를 배정하는 경우가 있다(account_id로만 묶으면 행이 쪼개져 듬성듬성 빈다).
4. **IS 지표를 찾을 때는 CIS도 후보에 넣는다**(`resolve_metric`). 별도 손익계산서 없이 포괄손익계산서 하나로만 공시하는 회사(HD한국조선해양 등)에서 매출~순이익이 통째로 비는 문제의 방지책이다.
5. **감가상각비는 DART API에 원래 없는 회사가 많다**(주석 항목이라 `fnlttSinglAcntAll` 범위 밖). 이 경우 오너 어닝 행이 비는 게 정상이며 다른 값으로 대체 추정하지 않는다(가치평가의 DCF는 투자분석 F섹션의 FCF로 자동 폴백).
6. **반기보고서 누적은 add-필드 우선**(4단계 규칙). (E) 추정의 비교 필드도 동일 규칙.
7. 값이 없는 셀은 0이 아니라 **빈 칸 또는 NA()**(차트에서 끊김으로 표시). 청산가치 적용비율 등 조정 가능한 계수는 리터럴이 아니라 **셀 참조**로 수식에 넣는다.
8. 차트 임베드 시작 열은 하드코딩하지 말고 `get_column_letter(2 + 기간수 + 2)`로 계산한다(표와 겹침 방지).
9. 실효세율은 세전이익 ≤ 0이면 NA, 그 외 0~50% 클램프(적자 연도 ROIC 폭주 방지).

## 5-3. "투자판단 종합"·"버핏멍거_가치평가"·"가치평가_결론"까지 자동으로 이어서 만들기

`--period annual`로 투자분석 시트를 만들었으면 멈추지 말고 아래를 이어서 실행한다. 중간에 "가치평가도 할까요?"라고 묻지 않는다.

1. `skills/investment-thesis-writer/scripts/fetch_business_description.py`로 사업의 내용 원문 수집.
2. 웹 검색으로 산업 동향·경쟁사·점유율·리스크·금리(할인율용) 보강 — 출처 URL을 남긴다.
3. 이미 계산된 투자분석 결과(등급·위험신호·PER 등)와 모순되지 않게 정성 텍스트 작성.
4. `content.json`(투자판단 종합) + `valuation_content.json`(가치평가) 작성 — 스키마와 작성 원칙은 `skills/investment-thesis-writer/SKILL.md` 참고. 성장률·할인율 가정은 근거 없이 지어내지 않는다.
5. `skills/investment-thesis-writer/scripts/build_thesis_sheet.py <xlsx> content.json` — **`--outdir` 지정 금지**(같은 파일에 시트 추가).
6. `skills/investment-thesis-writer/scripts/build_valuation_sheet.py <xlsx> valuation_content.json` — 역시 `--outdir` 지정 금지.
7. **마지막으로 `valuation-verdict` 스킬을 실행**해 같은 파일 **맨 앞에** "가치평가_결론" 시트(적정주가·괴리율·목표주가 범위·판정·신뢰도)를 추가한다:
   ```
   python plugins/valuation-verdict/skills/valuation-verdict/scripts/valuation_verdict.py \
       --source dart --cache-dir <이 스킬의 cache 폴더> --corp-code <corp_code> \
       --xlsx <같은 xlsx 경로> [--assumptions assumptions.json]
   ```
   - 할인율(rf·베타·ERP)·영구성장률·목표 PER 가정은 **2번 웹 리서치 결과로 JSON을 만들어 `--assumptions`로 넘긴다**(결정 방법은 valuation-verdict SKILL.md 2번 섹션). 안 넘기면 시장 기본값이 쓰이고 "이 정보들은 정확하지 않습니다"로 표시된다.
   - 결과 해석과 사용자에게 말하는 순서는 valuation-verdict SKILL.md 3~4번 섹션을 따른다.
8. 모든 시트가 끝난 뒤 `python /mnt/skills/public/xlsx/scripts/recalc.py <xlsx>`를 실행해 수식 오류 0을 확인한다(적자 연도 실효세율 NA 등 의도된 NA는 예외로 설명).

"재무제표만"/"분기만" 요청이면 이 단계 전체를 건너뛴다.

## 6. 저장 및 전달

- 파일명은 5단계 그대로(시트만 추가됨). 출력 폴더에 저장 후 전달한다.
- 완료 요약: 사용한 fs_div, 채워진 분기/연도 수, corp_code, 매칭 실패 지표 목록, 5-3까지 했다면 웹 리서치 출처·가정의 근거, 그리고 **가치평가_결론의 한 줄 판정(적정주가·상승여력·판정·신뢰도)**.

## 오류 처리

- `status != '000'` 응답은 `message`를 그대로 보고하고 중단(`013` 데이터 없음, `020` 한도 초과 등). 한도 초과는 간격을 두고 재시도, 계속 실패하면 사용자에게 알린다.
- 동일 기업명이 여러 corp_code에 매칭되면 반드시 사용자 확인 후 진행.
