# DART 재무제표 추출 및 엑셀 생성

기업명 하나를 입력받아 DART Open API로 재무제표를 수집하고, 최근 12개 분기와 최근 5개 사업연도 재무제표를 2개 시트 엑셀 파일로 만든다. 아래 순서를 그대로 따른다.

> **범위 확인 질문은 유지한다.** "OO 년 분석해줘"처럼 기간만 언급된 요청에는 (분기/연간/기업비교 등 진행 방식이 여러 갈래일 수 있으므로) 어떤 범위로 진행할지 선택지를 먼저 제시해도 된다. 다만 사용자가 "재무제표+투자분석"(또는 이와 동등한 전체 범위)을 선택하면, 그 뒤로는 **투자판단 종합까지 자동으로 이어서 진행**하고 중간에 다시 묻지 않는다 — 아래 5-3 참고.

## 0. 설정 영역 (Configuration)

아래 값들은 이 스킬의 조정 가능한 설정이다. 사용자가 별도로 요청하지 않는 한 기본값을 사용한다.

| 설정 항목 | 기본값 | 설명 |
|---|---|---|
| `DART_API_KEY` | (사용자 제공) | Cowork는 격리된 환경에서 실행되어 OS 환경 변수를 상속받지 못하므로, 스킬 시작 시 대화 맥락에 값이 없으면 사용자에게 직접 요청한다. 받은 값은 매번 `scripts/corp_code_lookup.py`와 `scripts/fetch_financials.py`를 실행할 때 `--api-key <값>` 인자로 전달한다. 값 자체를 요약, 로그, 캐시 파일, 최종 산출물(엑셀) 어디에도 노출하지 않는다. |
| `KRX_AUTH_KEY` | (사용자 제공, 선택) | "투자분석" 시트의 주가 연동 지표(PER·PBR·PSR·시가총액)에만 필요하다. 없으면 그 부분만 건너뛰고 나머지는 정상 진행한다. KRX Open API "유가증권 일별매매정보" 서비스 인증키를 `scripts/fetch_stock_price.py --auth-key <값>` 형태로 전달한다. DART_API_KEY와 마찬가지로 로그·산출물에 노출하지 않는다. `data-dbg.krx.co.kr` 도메인을 호출하므로, 허용 목록에 없다면 먼저 사용자에게 설정(코드 실행 → 네트워크 송신 허용 → 추가 허용 도메인)을 요청한다. 인증키 발급과 별개로 KRX 마이페이지에서 "유가증권 일별매매정보" 서비스 자체에 대한 이용 승인이 되어 있어야 하며, 안 되어 있으면 스크립트가 "Unauthorized API Call" 계열 에러를 명확히 알려준다. |
| `FS_DIV` | `CFS` (연결재무제표) | 응답의 `list`가 비어 있으면 `OFS`(별도재무제표)로 자동 재시도한다. 어떤 구분을 썼는지 최종 산출물에 표기한다. |
| `분기 수` | 12 | 최근 N개 분기. |
| `연도 수` | 5 | 최근 N개 사업연도. |
| 분기 시트명 | `분기_재무제표` | 사용자가 명시한 이름 그대로 고정. |
| 연간 시트명 | `연간_재무제표` | 사용자가 명시한 이름 그대로 고정. |
| 파일명 규칙 | `{기업명}[_연간|_분기]_{YYYYMMDD}.xlsx` | YYYYMMDD는 실행 당일(로컬 날짜). 접미사는 아래 0-1a 참고. |
| 시장 구분 확인 | KOSPI(코스피, corp_cls='Y')만 허용 | company.json API로 확인, 코스닥/코넥스면 사용자에게 확인 후 진행 여부를 묻는다. |

**API 키 처리:** 대화 시작 시 사용자가 아직 DART_API_KEY를 알려주지 않았다면 먼저 물어본다. 한 번 받으면 같은 대화 안에서는 다시 묻지 않고 이후 모든 스크립트 호출에 재사용한다. 이 방식은 편의를 위해 명령줄 인자로 키를 넘기므로 대화 기록에 키 값이 그대로 남는다는 점을 사용자에게 짧게 안내한다.

## 0-1a. 연간/분기 — 어느 기간으로 파일을 만들지 (v0.6.0부터)

`build_workbook.py`와 `build_comparison_workbook.py` 둘 다 `--period {annual|quarterly|both}` 인자를 받는다. 사용자 요청 문구에서 판단한다:

- 요청에 **"년"·"연간"·"연도"·"사업연도"** 등의 표현이 있으면 → `--period annual` (연간 시트만 담은 파일 하나)
- 요청에 **"분기"** 표현이 있으면 → `--period quarterly` (분기 시트만 담은 파일 하나)
- 둘 다 없으면 → `--period both` (기본값, 기존처럼 한 파일에 분기+연간 다 담음)
- 한 요청에 "년"과 "분기"가 둘 다 있거나(예: "삼성전자 년/분기 둘 다 분석해줘") 사용자가 명시적으로 둘 다 원하면, `--period annual`과 `--period quarterly`를 각각 실행해 파일을 2개 만든다(자동으로 `both`를 쓰지 않는다 — 그러면 파일이 하나로 합쳐져 시트가 다시 많아진다).

파일명 접미사: `annual`→`_연간`, `quarterly`→`_분기`, `both`→접미사 없음(기존과 동일). 비교 모드는 `{기업명나열} 비교[_연간|_분기]_{YYYYMMDD}.xlsx` 형식.

**"년"/"연간" 요청이 오면 범위를 묻는 선택지를 제시해도 된다** (예: "5개년 재무제표+투자분석" / "재무제표만" / "분기로"). 사용자가 "5개년 재무제표+투자분석"(또는 이와 동등한 전체 범위)을 선택하면 그때부터는 0-1a 순서(1~4단계 → 4-1단계 → 5단계)에 이어 **5-3단계(투자판단 종합)까지 자동으로 계속 진행**하고, 중간에 "투자판단 종합도 만들까요?" 같은 걸 다시 묻지 않는다 — 파일 하나에 재무제표+투자분석+투자판단 종합이 전부 담긴 결과물이 최종 산출물이다. 투자분석 중 KRX 주가 연동 부분만 KRX_AUTH_KEY가 없으면 그 부분만 자연스럽게 비워두고, 그 사실을 완료 후 요약에서 알려주면 된다. 사용자가 명시적으로 "재무제표만", "투자분석 빼고" 라고 말한 경우에는 투자분석과 투자판단 종합 단계를 모두 건너뛴다.

예시:
- "HD한국조선해양 년 분석해줘" → `build_workbook.py ... --period annual` → `HD한국조선해양_연간_20260808.xlsx` (연간_재무제표, 지표_연간[표+차트 임베드], 투자분석, 원본데이터) — **이 전체가 기본 동작이며 사용자에게 범위를 되묻지 않는다.**
- "HD한국조선해양 분기 분석해줘" → `--period quarterly` → `HD한국조선해양_분기_20260808.xlsx` (분기_재무제표, 지표_분기, 차트_분기, 원본데이터 — 투자분석은 원래 연간 데이터 기반이라 분기 파일에는 포함되지 않는다)
- "삼성전자, HD한국조선해양, 네이버 년 분석해줘" → `build_comparison_workbook.py ... --period annual` → `삼성전자, HD한국조선해양, 네이버 비교_연간_20260808.xlsx` (시트: `최근5년 비교` + 회사별 숨김 상세 시트)
- "삼성전자, HD한국조선해양, 네이버 분기 분석해줘" → `--period quarterly` → `... 비교_분기_20260808.xlsx` (시트: `12분기 비교` + 회사별 숨김 상세 시트)

## 0-1. 여러 기업을 요청받았을 때 — "나열" vs "비교" 구분

사용자가 기업을 2개 이상 언급하면 요청 문구에 **"비교"**(또는 "비교해줘", "나란히", "vs" 등 명백히 비교 의도인 표현)가 포함되어 있는지로 분기한다.

- **"비교" 표현이 없는 단순 나열** (예: "삼성전자, LG화학, 카카오 재무제표 뽑아줘"): 아래 1~6단계를 **기업마다 독립적으로 반복**해서, 기업별로 별도의 엑셀 파일을 만든다.
- **"비교" 표현이 있음** (예: "삼성전자, LG화학, 카카오 비교해줘"): 1~4단계(기업 고유번호 조회 + 원자료 수집)는 기업마다 각각 수행해 `cache/`에 데이터를 쌓아두되, 5단계(엑셀 작성)에서는 `scripts/build_workbook.py`가 아니라 **`scripts/build_comparison_workbook.py`를 한 번만** 실행해 비교용 엑셀 파일 1개를 만든다.
  ```
  python scripts/build_comparison_workbook.py "<corp_code1>:<기업명1>" "<corp_code2>:<기업명2>" ... --period <annual|quarterly|both> [--years 5] [--quarters 12] [--outdir /mnt/user-data/outputs]
  ```
  - `--period`는 0-1a를 따른다. 사용자가 "년"/"분기"를 명시하지 않았으면 `both`(기본값)로 실행한다.
  - 파일명은 스크립트가 자동으로 `{기업명1}, {기업명2}, {기업명3} 비교[_연간|_분기]_{YYYYMMDD}.xlsx` 형식으로 만든다 (예: `삼성전자, LG화학, 카카오 비교_연간_20260805.xlsx`).
  - 회사마다 상장 시기·공시 이력이 달라 보유한 기간(분기/연도)이 서로 다를 수 있다. 이 스크립트는 요청한 기업들의 "합집합" 기간 축을 함께 쓰도록 자동으로 맞춘다 — 특정 회사가 특정 기간 데이터가 없으면 그 회사의 해당 구간은 그래프에서 값이 끊긴(공백) 상태로 표시되며, 없는 데이터를 0으로 지어내지 않는다.
  - `--period both`(기본값)일 때 산출물은 눈에 보이는 시트 딱 2개(`12분기 비교`, `최근5년 비교`), `annual`/`quarterly`면 그중 해당하는 시트 1개만 담긴다. 각 시트 상단에 지표별·회사별 데이터 표(회사가 컬럼 블록, 지표가 행)가 있고, 그 아래에 지표 하나당 꺾은선 차트 하나(회사=계열)가 이어진다. 표시되는 지표는 매출액·매출원가·매출총이익·영업이익·당기순이익·유동자산·매출채권및기타채권·유동부채·경상이익·자산·부채·이익잉여금·현금및현금성자산의증가·자기자본비율·부채비율·매출총이익률·원가율·영업이익률·순이익률 총 19개이며, 비율 6개를 포함해 **전부 꺾은선 그래프**로 통일한다(막대그래프 사용 안 함). 회사별 원자료·상세 계산 시트는 감사(audit) 목적으로 존재하지만 전부 숨김 처리되어 있다.

## 1. 기업 고유번호(corp_code) 조회

DART API는 기업명이 아니라 8자리 `corp_code`로 조회한다.

1. `scripts/corp_code_lookup.py --api-key <DART_API_KEY> "<기업명>"`을 실행해 `corpCode.xml`(캐시가 7일 이상 오래됐으면 `https://opendart.fss.or.kr/api/corpCode.xml`에서 재다운로드, ZIP)에서 기업명을 매칭한다.
2. 동일한 이름이 여러 개면(자회사, 유사 상호 등) 후보 목록을 사용자에게 보여주고 선택받는다.
3. `company.json` API(`https://opendart.fss.or.kr/api/company.json`)로 `corp_cls`(법인구분: Y=코스피, K=코스닥, N=코넥스, E=기타)를 확인한다. Y가 아니면 사용자에게 알리고 계속할지 확인한다.

## 2. 대상 연도·보고서 목록 산정

- 연간 시트: 오늘 기준 최근 5개 사업연도의 사업보고서(`reprt_code=11011`).
- 분기 시트: 최근 12개 분기를 채우기 위해 필요한 보고서 목록을 만든다. 한 사업연도에는 4종 보고서가 필요하다.
  - `11013` 1분기보고서 (1~3월)
  - `11012` 반기보고서 (1~6월 누적)
  - `11014` 3분기보고서 (7~9월, 동시에 1~9월 누적 필드도 포함)
  - `11011` 사업보고서 (1~12월 누적)
- 아직 공시되지 않은 최신 분기(예: 반기보고서 법정 제출기한 전)는 건너뛰고, 그 이전 분기부터 역순으로 12개를 채운다. API 응답의 `status`가 `013`(조회된 데이터 없음)이면 해당 보고서가 아직 없는 것으로 간주한다.

## 3. 재무제표 원자료 조회

`scripts/fetch_financials.py --api-key <DART_API_KEY> <corp_code> <연도> <보고서코드> [fs_div]`로 각 (연도, reprt_code) 조합마다 `fnlttSinglAcntAll.json`을 호출한다.

```
GET https://opendart.fss.or.kr/api/fnlttSinglAcntAll.json
    ?crtfc_key={DART_API_KEY}&corp_code={corp_code}
    &bsns_year={연도}&reprt_code={보고서코드}&fs_div={FS_DIV}
```

- 응답 `list`의 각 원소를 `sj_div` 값으로 분류한다: `BS`=재무상태표, `IS`=손익계산서, `CIS`=포괄손익계산서, `CF`=현금흐름표. (`SCE` 자본변동표는 이번 산출물 범위 밖이므로 제외.)
- 계정을 매칭할 때는 `account_nm`(계정명)이 아니라 `account_id`(XBRL 표준계정ID)로 매칭한다. 같은 계정이라도 보고서마다 라벨 표기가 미세하게 다를 수 있다.
- 원자료는 재계산 방지를 위해 `cache/{corp_code}_{연도}_{reprt_code}_{fs_div}.json`에 저장해두고 재사용한다.
- 자세한 필드 설명과 reprt_code/sj_div 코드표는 `references/dart_api_reference.md`를 참고한다.

## 4. 분기 실적 계산 — 반드시 아래 구분을 지킨다

**재무상태표(BS)는 시점(저량) 데이터다.** 특정 시점의 잔액이므로 각 분기 말 보고서의 `thstrm_amount`를 그대로 쓴다. 뺄셈을 하지 않는다.

**손익계산서·포괄손익계산서·현금흐름표(IS/CIS/CF)는 흐름(유량) 데이터다.** DART 응답에는 두 금액 필드가 함께 온다.

- `thstrm_amount` (당기금액): 1분기·3분기보고서에서는 **해당 분기 단독(3개월)** 금액, 반기보고서에서는 **반기 누적(6개월)** 금액, 사업보고서에서는 **연간 누적(12개월)** 금액.
- `thstrm_add_amount` (당기누적금액): 1분기·3분기보고서에만 존재하며, **연초부터 해당 시점까지의 누적** 금액(1분기는 3개월 누적=단독과 동일, 3분기는 9개월 누적).

이를 바탕으로 분기별 실적은 다음과 같이 계산한다.

- **1분기** = 1분기보고서 `thstrm_amount` (그대로 사용, 계산 불필요)
- **2분기** = 반기보고서 `thstrm_amount`(6개월 누적) − 1분기보고서 `thstrm_amount`(3개월)
- **3분기** = 3분기보고서 `thstrm_amount` (이미 3개월 단독 값이므로 그대로 사용, 계산 불필요)
- **4분기** = 사업보고서 `thstrm_amount`(12개월 누적) − 3분기보고서 **`thstrm_add_amount`**(9개월 누적)

> ⚠️ 4분기 계산의 흔한 실수: 3분기보고서의 `thstrm_amount`(3개월 단독)를 사업보고서 값에서 빼면 안 된다. 그러면 "12개월 − 3개월"이 되어 4분기가 아니라 "1·2·4분기 합"이 산출된다. 반드시 3분기보고서의 **9개월 누적 필드(`thstrm_add_amount`)**를 사업보고서 값에서 빼야 4분기 단독 실적이 나온다.
>
> 실행 전 삼성전자 등 데이터가 풍부한 종목 1개로 `thstrm_add_amount` 필드가 실제로 채워져 있는지 먼저 확인하고(비어 있는 경우가 드물게 있음), 비어 있으면 대체 로직(1~2분기 합을 반기 누적값과 대조해 검증한 뒤, 3분기 누적 = 반기 누적 + 3분기 단독으로 직접 계산)을 사용한다.

## 4-1. "투자분석" 시트용 추가 데이터 수집 (v0.4.0부터)

이 단계는 5단계(엑셀 작성) 전에 완료해야 하며, 실패해도 5단계는 계속 진행한다(해당 부분만 빈 칸/안내 문구로 남음).

1. **DART 추가 공시 4종** (KRX 키 불필요, DART_API_KEY만 있으면 됨):
   ```
   python scripts/fetch_extra_disclosures.py --api-key <DART_API_KEY> <corp_code> <최근사업연도> 11011
   ```
   주식총수현황·배당·최대주주현황·자기주식현황을 한 번에 가져와 `cache/extra_{corp_code}_{연도}_11011.json`에 저장한다.

2. **KRX 종가** (KRX_AUTH_KEY가 있을 때만): 연간 시트에 쓸 각 사업연도 말일 기준으로, 연도별로 한 번씩 실행한다.
   ```
   python scripts/fetch_stock_price.py --auth-key <KRX_AUTH_KEY> <stock_code> <YYYY1231>
   ```
   - `stock_code`는 `corp_code_lookup.py` 결과의 6자리 종목코드.
   - KRX Open API "유가증권 일별매매정보"(공식 스펙 확정: 종가=`TDD_CLSPRC`, 시가총액=`MKTCAP`, 상장주식수=`LIST_SHRS`)를 쓴다.
   - 휴장일이면 스크립트가 자동으로 며칠 전까지 거슬러 올라간다.
   - 이 호출은 `data-dbg.krx.co.kr`로 나간다. 네트워크 오류가 나면 Cowork 설정에서 이 도메인이 허용되어 있는지 사용자에게 먼저 확인한다.
   - "Unauthorized API Call" 에러가 나면 인증키 발급과는 별개로, KRX 마이페이지에서 "유가증권 일별매매정보" 서비스 자체에 대한 이용 승인이 필요하다는 뜻이므로 사용자에게 안내한다.

## 5. 엑셀 작성

```
python scripts/build_workbook.py <corp_code> <기업명> --period <annual|quarterly|both> [--years 5] [--quarters 12] [--outdir /mnt/user-data/outputs]
```

`--period`는 0-1a를 따른다. `annual`이면 연간 관련 시트만, `quarterly`면 분기 관련 시트만, `both`(기본값, 사용자가 "년"/"분기"를 말하지 않았을 때)면 기존처럼 전부 한 파일에 담는다. 반드시 `/mnt/skills/public/xlsx/SKILL.md`의 규칙(전문적인 글꼴, 수식 사용, 색상 규칙, `recalc.py` 무결성 검증)을 함께 따른다.

- **분기_재무제표**: 행 = 계정과목(재무상태표 → 손익계산서 → 현금흐름표 순서, 각 섹션은 `sj_nm`으로 구분), 열 = 최근 12개 분기(오래된 순 → 최근 순). 원본 누적 값(반기 누적, 9개월 누적, 연간)은 별도의 "원본데이터" 보조 열/시트에 입력값으로 두고, 2·4분기 열은 `=반기누적셀-1분기셀` 같은 실제 엑셀 수식으로 계산해 감사(audit) 가능하게 만든다. 하드코딩된 숫자로 2·4분기를 채우지 않는다.
- **연간_재무제표**: 행 = 계정과목, 열 = 최근 5개 사업연도. 사업보고서의 `thstrm_amount`를 그대로 입력값으로 사용한다.
- 각 시트 상단에 `fs_div`(연결/별도), 데이터 출처(DART corp_code, 접수번호 `rcept_no`), 생성일을 메모로 남긴다.
- 작성 후 `python scripts/office/recalc.py output.xlsx` (xlsx 스킬 경로 기준)를 실행해 수식 오류가 없는지 검증한다.

## 5-1. 추세 지표 및 그래프 (자동 생성)

`build_workbook.py`는 위 2개 시트에 더해 **지표_분기 / 차트_분기 / 지표_연간** 시트를 함께 만든다(분기 차트는 `차트_분기`라는 별도 시트, 연간 차트는 별도 시트 없이 `지표_연간` 시트 안에 표 오른쪽 I열부터 바로 임베드된다 — v0.7.0부터). 별도 실행 스크립트는 없고 `build_workbook.py` 실행 한 번으로 전부 생성된다.

- **지표\_{분기|연간}**: `분기_재무제표`/`연간_재무제표` 셀을 참조하는 수식으로 아래 지표를 계산한다(하드코딩 없음).
  - 기본 지표: 매출액, 매출원가, 매출총이익(=매출액−매출원가), 영업이익, 당기순이익, 경상이익(=영업이익+금융수익−금융비용+기타수익−기타비용), 유동자산, 매출채권및기타채권, 유동부채, 자산총계, 부채총계, 자본총계, 이익잉여금, 현금및현금성자산의증가(현금흐름표의 순증가 항목)
  - 비율 지표(%): 자기자본비율(자본총계/자산총계), 부채비율(부채총계/자본총계), 매출총이익률, 원가율, 영업이익률, 순이익률 (모두 매출액 대비)
- **차트\_{분기|연간}**: 지표 시트를 참조하는 openpyxl 차트 6개.
  - 그래프1(꺾은선): 매출액·매출원가·매출총이익
  - 그래프2(꺾은선): 매출총이익·영업이익·당기순이익·경상이익
  - 그래프3(꺾은선): 유동자산·유동부채·자산총계·부채총계
  - 그래프4(꺾은선): 매출액·매출채권및기타채권
  - 그래프5(꺾은선): 이익잉여금·현금및현금성자산의증가
  - 그래프6(막대, 계열 6개): 자기자본비율·부채비율·매출총이익률·원가율·영업이익률·순이익률
- **계정명 매칭 한계**: 위 지표들은 회사마다 표기가 다를 수 있는 `account_nm`을 우선순위 후보 목록으로 탐색해 매칭한다(예: "기타수익" 또는 "기타영업외수익"). 특정 회사에서 매칭에 실패한 지표는 지표 시트에 빈 칸으로 남고, 시트 하단에 어떤 지표를 못 찾았는지 빨간 글씨로 표시된다. 이 경우 원인은 값을 지어내지 않고 사용자에게 "이 지표는 이 회사 공시에서 찾지 못했습니다"라고 그대로 안내한다.
- **IS/CIS 폴백 (v0.6.1)**: HD한국조선해양처럼 별도 손익계산서(IS) 없이 포괄손익계산서(CIS) 하나로만 손익을 공시하는 회사가 있다(매출액·영업이익·당기순이익 등이 DART 응답에서 `sj_div="CIS"`로 잡힘). `resolve_metric`은 손익 계정(`sj_div="IS"`로 등록된 지표)을 찾을 때 IS뿐 아니라 CIS도 함께 후보로 탐색하도록 되어 있다 — 이 폴백이 빠지면 조선·중공업 등 일부 업종에서 매출액~순이익이 통째로 빈 칸이 되는 문제가 재발하니, 이 스킬을 수정할 일이 있으면 이 부분을 건드리지 않도록 주의한다.

## 5-2. "투자분석" 시트 (v0.4.0부터)

첨부 참고자료(기업 분석 리포트 작성법)의 체크리스트를 반영한 시트로, `연간_재무제표`/`지표_연간`을 참조하는 수식과 4-1단계 캐시를 함께 사용해 자동 생성된다.

- **A. 회사 개황**: `cache/company_{corp_code}.json` (corp_code_lookup.py 실행 시 자동 저장됨)에서 기업명·대표자·설립일·업종코드·주소·홈페이지를 가져온다.
- **B. 재무지표(연간 5개년)**: 건전성(자기자본비율·부채비율·유동비율·당좌비율·고정비율), 수익성(매출총이익률·영업이익률·세전순이익률·순이익률·ROE·ROA), 성장성(매출·영업이익·순이익 성장률(YoY)·총자산회전율·매출채권회전율). 모두 셀 참조 수식.
- **C. 위험 신호 점검**: 유동부채>유동자산, 차입금 과다(자기자본비율<20%), 순자산 마이너스(채무초과), 매출채권 급증(매출증가율 대비 +20%p 이상 — 임의 기준이므로 필요시 조정), 영업활동현금흐름 마이너스. 연도별 "양호"/"⚠ 위험"으로 표시.
- **D. 청산가치**: 최신 연도 기준 조정자산(현금·유가증권 100%, 매출채권 85%, 재고·투자자산·유형자산 50%, 무형자산·기타유동자산 0%) 합계에서 총부채를 뺀 값.
- **E. 주가 연동 지표**: 4-1단계에서 가격 캐시를 가져온 연도만 종가·시가총액·PER·PBR·PSR을 채운다. 캐시가 없는 연도는 "가격 데이터 없음"으로 표시하고 계산을 건너뛴다.
- **F. 배당·대주주·자기주식**: 4-1단계의 DART 추가 공시 캐시에서 최신 사업연도 값을 그대로 옮긴다.
- **N. 투자 판단 (v0.8.0부터 자동 평가)**: 7개 항목의 등급(A~E)과 근거 메모를 스크립트가 자동으로 채운다. 등급 규칙은 **최근 5개년 중 기준 충족 연수**로 A(5년)·B(4년)·C(3년)·D(2년)·E(0~1년)를 매기되, **기준에 계속 미달해도 5년 내내 값이 개선되면 A로 승격**한다(연수가 5년 미만이면 같은 비율로 환산). 항목별 기준은 첨부 참고자료를 그대로 코드화했다:
  - 재무건전성 = 자기자본비율 40%↑ + 부채비율 200%↓ + 유동비율 100%↑
  - 수익성 = 영업이익률 5%↑ + ROE 10%↑ + ROA 5%↑
  - 성장성 = 매출성장률 10%↑ + 영업이익성장률 플러스 + 총자산회전율 1.0↑
  - 자산 기준 저평가 = PBR 1.0 미만 / 수익력 기준 저평가 = PER 15배 미만 (둘 다 KRX 주가 캐시가 있어야만 평가되고, 없으면 "-"와 안내 문구가 들어간다)
  - 주주 중시 자세 = 배당성향(30%↑ A, 20%↑ B, 0 초과 C, 그 외 D) + 자기주식 이력. 참고자료가 강하게 경고한 "증자로 자금을 해결하는 기업"인지는 유상증자 공시를 따로 봐야 해서 자동 판별하지 않고 메모에 그 사실을 남긴다.
  - **사업역량은 자동 평가하지 않는다** — 사업 단순성·거래처 분산·경쟁력은 공시 수치로 판단할 수 없어 "(직접 입력)"으로 남기고 무엇을 확인해야 하는지만 안내한다. 사용자가 요청하면 Claude가 사업보고서 내용을 근거로 초안 의견을 제시할 수 있다.
  - 등급은 하위 지표 등급을 점수화(A=5…E=1)해 평균 낸 뒤 반올림 구간으로 산출한다. 근거 메모에는 하위 지표별 "N년 중 K년 충족(등급)"과 지속개선 승격 여부가 그대로 적힌다.

- **C(확장)**: 이자보상배율 1 미만(이자도 못 갚는 수준) 위험 신호 추가로 총 6종
- **E. 현금전환주기(CCC)**: 매출채권회수기간+재고자산처리기간−매입채무지불기간(일). 마이너스에 가까울수록 우량.
- **F. 잉여현금흐름(FCF)**: 영업활동현금흐름−CAPEX(유형자산의 취득), FCF마진(%)도 함께.
- **G. 현금흐름 3단 구분**: 영업·투자·재무활동현금흐름을 각각 표시하고, 3단 합계로 '현금및현금성자산의증가'와 대조 검증.
- **H. DuPont 분해**: ROE = 순이익률 × 총자산회전율 × 레버리지(자산/자기자본)로 분해해 B섹션 ROE와 교차 검증.
- **I. ROIC/NOPLAT (간이)**: NOPLAT = 영업이익×(1−실효세율), 투하자본(간이) = 자기자본+비유동부채로 근사. 이자부부채만 골라내는 정교한 버전이 아님을 시트에 명시.
- **J. 자산·부채 구성비 변화(간이)**: 유동/비유동 자산·부채가 총자산·총부채 대비 몇 %인지. 부채 구성이 단기 쪽으로 쏠리는지 파악.
- **K. 외환손익**: 외화환산손익·파생상품손익. 많은 회사에 아예 없는 게 정상이라 매칭 실패 경고 목록에는 포함하지 않고, 빈 값이면 그 자체를 안내 문구로 표시한다.
- 산출 지표 이름이 L(주가 연동)·M(배당 등)·N(투자 판단)으로 재배치되었을 뿐 내용은 이전과 동일하다.

## 5-3. "투자판단 종합" 시트까지 자동으로 이어서 만들기 (v0.9.1부터)

`--period annual`로 "투자분석" 시트를 만든 경우(즉 사용자가 재무제표만이 아니라 투자분석까지 원한 경우), **여기서 멈추지 말고 곧바로 `investment-thesis-writer` 스킬의 절차를 이어서 실행**해 같은 파일에 "투자판단 종합" 시트까지 추가한다. 사용자가 회사 이름만 말했어도(예: "삼성전자"), 앞서 범위 확인 질문에서 "재무제표+투자분석"을 골랐다면 이 단계까지가 한 번의 요청으로 처리해야 할 작업이다. 중간에 "투자판단 종합도 만들까요?"라고 다시 묻지 않는다.

절차 요약(자세한 건 `skills/investment-thesis-writer/SKILL.md` 참고):
1. `skills/investment-thesis-writer/scripts/fetch_business_description.py`로 DART 사업의 내용 원문 수집
2. 웹 검색으로 산업 동향·경쟁사·시장점유율·리스크 뉴스 등 최신 정보 보강
3. 이미 만든 "투자분석" 시트의 정량 결과(등급, 위험신호, PER/PBR 등)를 참고해 서로 모순되지 않게 정성 텍스트 작성
4. `content.json` 작성 (스키마는 investment-thesis-writer의 SKILL.md 참고)
5. `skills/investment-thesis-writer/scripts/build_thesis_sheet.py <5단계에서 만든 xlsx 경로> content.json` 실행 — **`--outdir`를 지정하지 않는다**. 그래야 새 파일이 아니라 같은 파일에 시트가 추가되어, 최종 산출물이 "재무제표+투자분석+투자판단 종합"이 전부 담긴 파일 하나가 된다.

이 단계는 DART_API_KEY 재사용 외에 추가로 사용자에게 확인받을 게 없다(웹 검색은 이미 허용된 도구). "재무제표만" 또는 "분기만" 요청이었다면 이 5-3단계 자체를 건너뛴다(투자분석 시트가 없으면 투자판단 종합도 만들 수 없다).

## 6. 저장 및 전달

- 파일명: `{기업명}[_연간|_분기]_{YYYYMMDD}.xlsx` (0-1a 참고. 예: `삼성전자_연간_20260804.xlsx`) — 5-3단계까지 실행했어도 파일명은 그대로이고 시트만 추가된다.
- Cowork의 출력 폴더에 저장하고 사용자에게 전달한다.
- 완료 후 요약: 어떤 fs_div(연결/별도)를 사용했는지, 12분기 중 실제로 채워진 분기 수(공시 지연으로 못 채운 경우 몇 분기가 비었는지), 사용한 corp_code, 매칭에 실패해 빈 칸으로 남은 지표가 있으면 그 목록(`build_workbook.py`의 표준출력 JSON `missing_indicators` 필드), 그리고 5-3단계까지 실행했다면 어떤 웹 검색으로 투자판단 종합을 보강했는지와 성장률 가정의 근거를 간단히 알려준다.

## 오류 처리

- `status != '000'`인 API 응답은 `message` 필드를 그대로 사용자에게 보고하고 중단한다(예: `013` 데이터 없음, `020` 사용 한도 초과).
- 사용 한도(요청 제한) 초과 시 재시도 간격을 두고, 계속 실패하면 사용자에게 상태를 알린다.
- 동일 기업명이 여러 corp_code에 매칭되면 반드시 사용자 확인을 받은 후 진행한다.
